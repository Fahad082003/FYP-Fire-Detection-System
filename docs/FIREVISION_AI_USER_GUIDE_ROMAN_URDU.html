A · Shuru karne se pehle

1. Ye Guide Kis Ke Liye Hai?

Ye guide aam istemaal karne wale ke liye hai, programmer hona zaroori nahi. Is mein qadam ba qadam likha hai:

  1. FireVision AI ko pehli dafa computer par kaise install karein.
  2. Roz kaise chalayein (start) aur band karein.
  3. Website (dashboard) ka har hissa kya karta hai.
  4. Har feature ko khud test kaise karein, aur test ke baad screen par kya dikhna chahiye.
  5. Masla aaye to kya karein.

FireVision AI ek line mein

FireVision AI building ka "smart chowkidar" hai. Camera mein AI aag, dhuwan aur insaan pehchaanta hai. Sensors garmi aur dhuwan napte hain. Khatra ho to screen par alarm aata hai, SMS/Email/Push jaate hain, sprinklers chal sakte hain, aur naqshe par mehfooz raasta dikhta hai.

Guide kaise parhein

  • Is tarah ke dabbe mein jo likha hai, wo computer mein type karna hai (ya copy-paste).
  • ✅ = test pass hone par yehi dikhna chahiye.
  • ⚠️ = dhyan dein, zaroori baat.
  • <project> ka matlab hai project ka folder, is computer par: C:\Users\m_fahad\Desktop\Project.

ℹ️ Note (2026-10-26 se): project ab Django par chalta hai (folder sentinel-django\): ek hi server dashboard, API aur live updates deta hai, address http://localhost:5291. Purana ASP.NET Core + Angular wala hissa hata diya gaya hai. Is guide ki tasveerein (screenshots) purane Angular dashboard se li gayi thin; Django dashboard mein wohi panels hain, bas thora sa design ka farq ho sakta hai.

3 hifazati usool (pehle parh lein)

⚠️ 1. Ye system test aur demo ke liye hai. Ise asli fire alarm ki jagah na lagayein. Asli building mein smoke detectors aur fire panel zaroori hain.

⚠️ 2. Test se pehle "Safe Test Mode" (Chapter 4) zaroor karein, warna test ke dauran asli SMS aur Email chale jayenge.

⚠️ 3. Kisi asli sprinkler, alarm ya camera ko bina ijazat aur bina safe tareeqe ke system se na jorein.

2. Pehli Dafa: Zaroori Software Install Karna

Ye kaam sirf ek dafa karna hai. Har software ki official website se download karein.

# Software Kahan se Kyun
1 Python 3.13 python.org (install mein "py launcher" tick rehne dein) Server (dashboard + API) aur AI service, dono ke liye
2 SQL Server 2019 ya naya (Developer, Express ya LocalDB, free) microsoft.com/sql-server Database
3 ODBC Driver 18 for SQL Server learn.microsoft.com (search: "ODBC Driver 18 for SQL Server") Python ko SQL Server se jorne ke liye

.NET SDK, Node.js, Angular CLI ya dotnet-ef ki ab zaroorat nahi. (Sirf browser wale automatic tests ke liye Node/npm chahiye, Chapter 17; ye zaroori nahi.)

Check karein ke Python install ho gaya:

✅ Version number dikhe, error nahi. ODBC Driver check: Start → "ODBC Data Sources (64-bit)" → Drivers tab mein "ODBC Driver 18 for SQL Server" ho.

PowerShell kaise kholein: Start menu → "PowerShell" likhein → Windows PowerShell par click.

3. Pehli Dafa: Project Ka Setup

Ye bhi sirf ek dafa.

Qadam 1: .env file banana (settings aur passwords)

  1. Project folder kholein: C:\Users\m_fahad\Desktop\Project.
  2. .env.example file ki copy banayein aur naam .env rakhein (is computer par .env pehle se bani hui hai).
  3. .env ko Notepad mein kholein aur ye bharein:
Line Kya likhna hai
Jwt__SigningKey= Lambi random chaabi (neeche command se banayein)
Device__ApiKey= Ek aur random chaabi (machines ka password)
Seed__AdminEmail= Login email, jaise admin@sentinel.local

Random chaabi banane ki command (PowerShell):

Jo text aaye, copy karke = ke baad paste karein. Device__ApiKey ke liye dobara chalayein.

⚠️ .env mein passwords hain. Ise kisi ko na bhejein, na internet par daalein.

4. Safe Test Mode (Test Se Pehle Zaroor)

Masla: is computer ki .env mein asli Twilio (SMS) aur Email ki settings hain. Test mein aag ya emergency bani to system asli logon ko asli SMS/Email bhej dega.

Hal: test ke dauran SMS aur Email band karna

  1. .env Notepad mein kholein.
  2. In lines ke shuru mein # laga dein (# wali line system parhta hi nahi):
#Notifications__Sms__TwilioAccountSid=...
#Notifications__Sms__TwilioAuthToken=...
#Notifications__Sms__FromNumber=...
#Notifications__Sms__Recipients=...
#Notifications__Email__SmtpHost=...
  1. Save karein. Server chal raha ho to band karke dobara chalayein (Chapter 5).

Is ke baad kya hoga:

  • SMS: Live Event Log mein "skipped (not configured)". Koi SMS nahi jayega.
  • Email: asal mein nahi jayega. Us ka poora text Server wali PowerShell window mein print hoga ("console mode"). Test ke liye ye behtareen hai.
  • Browser Push: sirf usi browser par jahan aap ne khud Enable Alerts dabaya ho.

Test khatam hone ke baad # hata dein taake asli alerts dobara chalein.

System band karna

Har window mein Ctrl + C dabayein, ya window band kar dein. Data database mein mehfooz rehta hai.

Database doosre PC se (office ↔ ghar)

Dono PCs par ek jaisa data rakhne ke liye database ek backup file (database\SentinelDb.bak) ban kar git se jata hai.

Kaam khatam karte waqt (jis PC par kaam kiya):

cd C:\Users\m_fahad\Desktop\Project
.\database\save.ps1
git add database\SentinelDb.bak
git commit -m "db: update"
git push

Doosre PC par kaam shuru karte waqt (pehle Server band karein):

git pull
.\database\load.ps1

"yes" likhein. ✅ "Restored SentinelDb…" aaye. Database na ho to ban jata hai, ho to poora badal jata hai.

⚠️ Ek waqt mein ek hi PC par kaam karein. Dono jagah data badla aur save/load bhool gaye, to ek jagah ka kaam mit jayega. Login wohi email/password chalta hai jo pehle PC par tha.

8. Test 1: Aag Ka Demo (Simulator)

Maqsad: dekhna ke aag lagne par poora system kaise react karta hai.

⚠️ Pehle Safe Test Mode (Chapter 4) karein. Is demo mein insaan danger zone mein aate hain, jo emergency hai, aur SMS/Email chalte hain.

Qadam:

  1. Window 1 (Server) chal rahi ho. Login karein.
  2. .env se apni Device__ApiKey copy karein.
  3. Nayi PowerShell window (Window 3):
cd C:\Users\m_fahad\Desktop\Project\sentinel-django
.\.venv\Scripts\python tools\simulator.py --device-key <yahan Device__ApiKey> --ignite "Ground Floor - Warehouse"

(Ya seedha .\start.ps1 -Simulator: ye simulator ki window khud khol deta hai.)

  1. Browser mein Dashboard dekhein.

✅ Kya dikhna chahiye (1–2 minute mein):

  • Cameras par boxes hilte hue. SIM DATA chip.
  • Warehouse Floor (Ground Floor - Warehouse) camera par laal aag ka dabba aur laal danger zone, hari "assembly point".
  • Upar pill laal: CRITICAL ALERT. Alarm lagatar bajta hai (Resolve karne ya 🔊 dabane tak).
  • Alert Logs mein naya incident, Location "Ground Floor - Warehouse", Severity High/Critical.
  • Live Event Log mein lines: incident khula, SMS "skipped", email (Server window mein print).
  • Ground Floor - Warehouse ke garmi/dhuwan gauges barhte hue.
  • Ground Floor - Warehouse ke Auto sprinklers khud chal jaate hain ("spraying"). Demo setting (SENTINEL_DEBUG, ya Alerts__AutoSprinklerOnSimulatedData=true) mein simulated data par bhi chalte hain; asli hardware nahi, sirf database.

Band karna: Window 3 mein Ctrl + C.

Camera lost check (simulator band karne ke baad):

  • ~10–12 second baad Alert Logs mein har camera ke liye ek incident, Source Camera lost: "Camera lost: no frames from … for 10 s".
  • Ground Floor - Warehouse ke cameras (jahan aag thi) High, baqi Medium.
  • Simulator dobara chalayein: Live Event Log mein "Camera … is sending frames again". Phir purane "Camera lost" incidents Resolve kar dein.

Simulator ke options:

Option Kaam Default
--ignite "Ground Floor - Lobby" Us zone mein foran aag (kai dafa likh sakte hain) —
--fps 2 Har camera ke frames per second 5
--fire-probability 0 Khud se random aag band 0.004
--telemetry-interval 5 Sensors kitne second baad 2

10. Test 3: Sensor Ko Garam Karna (PowerShell)

Maqsad: dekhna ke garmi barhne par Warning, Alarm aur Critical sahi waqt par aate hain.

Pehle ye kaam Swagger page se hota tha; Django mein Swagger page nahi hai. Ab hum PowerShell se seedha sensor ki reading bhejte hain, bilkul waise jaise asli sensor (machine) bhejta hai: X-Device-Key header mein .env wali Device__ApiKey.

Neeche purani tasveer sirf hawale ke liye hai (Swagger ab nahi hai):

Qadam A: tayyari

  1. Window 1 (Server) chal rahi ho aur browser mein Dashboard khula ho.
  2. Nayi PowerShell window kholein aur apni device key rakhein:
$key = '<yahan Device__ApiKey>'

Qadam B: garmi bhejna

  1. Sensor temp-b1 (Ground Floor - Warehouse ka temperature sensor; threshold 57°C). Ye command ek reading bhejti hai (yahan 30):
Invoke-RestMethod -Method Post -Uri http://localhost:5291/api/iot/sensors/temp-b1/readings -Headers @{ 'X-Device-Key' = $key } -ContentType 'application/json' -Body '{ "value": 30 }'

✅ Jawab mein sensor ka haal aaye: id = temp-b1, currentValue = 30, state = Normal. Ghalat key par 401 error.

  1. Ab -Body mein ek ek karke ye values bhejein (sirf number badlein), har dafa Dashboard dekhein:
Value Kya hona chahiye Hisaab
{ "value": 30 } ✅ Normal, kuch nahi 45.6 se kam
{ "value": 50 } ✅ Gauge peela (Warning), Live Event Log mein "Normal → Warning", incident nahi ≥ 57 × 0.8 = 45.6
{ "value": 60 } ✅ High incident + Ground Floor - Warehouse ke Auto sprinklers ON ≥ 57
{ "value": 75 } ✅ Critical incident + emergency notifications + sprinklers ≥ 57 × 1.25 = 71.25

Sensor IDs (ye demo data ke sensors hain, jo pehli dafa start par bante hain jab demo data on ho, Seed__DemoData ya SENTINEL_DEBUG; na milein to jawab mein "Sensor '…' not found"):

Zone Dhuwan (threshold 300 ppm) Garmi (threshold 57°C)
Ground Floor - Lobby smoke-a1 temp-a1
Ground Floor - Warehouse smoke-b1 temp-b1
First Floor - Server Hall smoke-c1 temp-c1

Dhuwan ke liye Critical = 300 × 1.5 = 450 ppm.

⚠️ Sensor ka data asli maana jata hai (SIMULATED nahi), is liye Alarm/Critical par Auto sprinklers chal jate hain. Is project mein sprinklers sirf database mein hain, koi asli hardware nahi. Test ke baad unhein OFF karein (Chapter 11).

13. Test 6: Naqsha Banana Aur Evacuation Raasta

A. Naqsha banana

  1. Upar Floor Plans → + New.
  2. Daen taraf Plan settings: Name ("Ground Floor"), Building ("Warehouse"), Floor (0), Width aur Height meters mein (jaise 30 × 20).
  3. (Ikhtiyari) Upload image (PNG/JPG): apne naqshe ki photo background mein (5 MB tak).
  4. Toolbar se drag karke banayein:
Tool Kya banana hai
+ Room Kamre / halls
+ Corridor Gallery
+ Wall Deewarein (kamron ke beech)
+ Door Deewar par darwaza (darwaze ke baghair raasta deewar paar nahi karta)
+ Exit Bahar nikalne ke darwaze (kam az kam ek)
+ Safe zone Assembly point
+ Danger zone Boiler room / khatarnak jagah
  1. Select / Move se kisi cheez par click → daen panel mein naam, size badlein. Delete key = mitana.
  2. Danger zone chunein → Linked camera/sensor zone mein list se Ground Floor - Warehouse chunein (likhne ki zaroorat nahi, spelling galat nahi hogi) (Ground Floor - Warehouse mein incident khula ho to ye khud active).
  3. Save. ✅ "Floor plan saved" message, title se "unsaved" hat jaye.

Zoom: mouse wheel ya + / − / Fit. Ek khana = 1 meter.

B. Raasta dekhna

  1. Dashboard → neeche Evacuation Route (estimate) panel → floor plan chunein.
  2. Naqshe par wahan click karein jahan insaan khara hai.
  3. ✅ Hari teer qareeb tareen exit tak, "Distance 14.8 m · ~12 s" jaisa likha.

C. Aag mein raasta badalna

  1. Ground Floor - Warehouse ke danger zone ke paas wala raasta dekh lein.
  2. Test 1 (simulator --ignite "Ground Floor - Warehouse") ya Test 3 (temp-b1 = 75) chalayein.
  3. ✅ Danger zone laal/active, aur raasta khud badal kar doosre exit ki taraf, danger se kam az kam 1 m door.
  4. Koi raasta na bache to ✅ saaf message: "No safe route…"
Pehle Aag ke baad

Yaad rakhein: waqt sirf andaza hai (faasla ÷ 1.2 m/s). Dhuwan, bheer, seedhiyan shamil nahi.

D. Aag kahan phailegi (risk heatmap)

Maqsad: aag lagne par dekhna ki system bataye agle kaun se kamre khatre mein hain.

  1. Naqshe mein kam az kam 2 kamre, unke beech deewar aur ek darwaza hon. Danger zone ka Linked zone = Ground Floor - Warehouse (A hisse wala naqsha).
  2. Ground Floor - Warehouse mein incident kholein: Emergency Dispatch (Ground Floor - Warehouse), ya simulator --ignite "Ground Floor - Warehouse".
