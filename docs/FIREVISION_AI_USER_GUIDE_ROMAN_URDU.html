A · Naye PC par pehli dafa

1. Ye Guide Kis Ke Liye Hai?

Ye guide aam istemaal karne wale ke liye hai, programmer hona zaroori nahi. Is mein qadam ba qadam likha hai:

  1. FireVision AI ko kisi bhi naye Windows PC par pehli dafa kaise install karein (Chapter 2–5).
  2. Roz kaise chalayein aur band karein (Chapter 7).
  3. Naye dashboard ka har page kya karta hai (Chapter 9).
  4. Har feature ko khud test kaise karein, aur test ke baad screen par kya dikhna chahiye (Chapter 10–19).
  5. Masla aaye to kya karein (Chapter 5 aur 21).

FireVision AI ek line mein

FireVision AI building ka "smart chowkidar" hai. Camera mein AI aag, dhuwan aur insaan pehchaanta hai. Sensors garmi aur dhuwan napte hain. Khatra ho to screen par alarm aata hai, SMS/WhatsApp/Telegram/Email/Push ja sakte hain, sprinklers chal sakte hain, naqshe par mehfooz raasta dikhta hai, aur har kamre mein kitne log hain ye bhi.

Guide kaise parhein

  • Is tarah ke dabbe mein jo likha hai, wo computer mein type karna hai (ya copy-paste; kaale dabbon par Copy button hai).
  • ✅ = test pass hone par yehi dikhna chahiye.
  • ⚠️ = dhyan dein, zaroori baat.
  • <project> ka matlab hai project ka folder, jahan aap ne project rakha (misaal C:\Users\<aap ka naam>\Desktop\Project). Neeche ki commands isi folder mein chalti hain.

ℹ️ Note (2026-11-04): dashboard ka naya design aa gaya hai (gehra rang, baen taraf menu). Page ke naam badle hain: Dashboard → Overview, Cameras → Live Cameras, Building Map → Floor Plan, AI Service → AI Settings, Reports → Reports & Analytics. Do naye pages: Occupancy & Heatmap aur Notifications. Is guide ki saari tasveerein naye dashboard ki hain aur nakli (simulated) test data dikhati hain, asli building nahi.

3 hifazati usool (pehle parh lein)

⚠️ 1. Ye system test aur demo ke liye hai, production ke liye tayyar ya certified nahi. Ise asli fire alarm ki jagah na lagayein. Asli building mein smoke detectors aur fire panel zaroori hain.

⚠️ 2. Test se pehle "Safe Test Mode" (Chapter 6) zaroor karein, warna test ke dauran asli SMS, WhatsApp, Telegram aur Email chale jayenge.

⚠️ 3. Sprinkler/relay ka button asli kaam hai. Kisi asli sprinkler, alarm ya camera ko bina ijazat aur bina safe tareeqe ke system se na jorein.

3. Naya PC (2/4): Project Laana Aur setup.ps1

Qadam 1: Project computer par laana

Tareeqa A (Git): PowerShell mein (misaal Desktop par):

cd $HOME\Desktop
git clone git@github.com:Fahad082003/FYP-Fire-Detection-System.git Project
cd Project

(git@github.com wala link GitHub par SSH key mangta hai. Repo ka maalik hi aap ko access de sakta hai.)

Tareeqa B (zip / USB): poora project folder copy karein (misaal Desktop\Project), phir PowerShell mein cd se us folder mein jayein. Ya folder kholein → khali jagah par Shift + Right click → "Open PowerShell window here" / "Open in Terminal".

✅ dir likhein: setup.ps1, start.ps1, stop.ps1, sentinel-django, ai-service, database nazar aayein.

Qadam 2: setup.ps1 chalana

.\setup.ps1

Agar laal error aaye "running scripts is disabled on this system", to ye chalayein:

powershell -ExecutionPolicy Bypass -File .\setup.ps1

setup.ps1 kya karta hai (har cheez ke aage [OK ] ya [FIX] aur hal likhta hai):

  1. Python 3.13 check.
  2. Dono .venv (Server aur AI service) banane aur packages install karne se pehle poochta hai: y likh kar Enter. Ye kuch minute leta hai.
  3. ODBC Driver for SQL Server check.
  4. .env na ho to .env.example se banane se pehle poochta hai (y). Purani .env ko kabhi nahi badalta.
  5. SQL Server aur SentinelDb check (sirf parhta hai, kuch nahi badalta).
  6. AI model files (ai-service\models\*.onnx, repo mein maujood) ka fingerprint (sha256) check.

Pehli dafa .env aur database ke [FIX] aana aam baat hai. Chapter 4 aur 5 karein, phir .\setup.ps1 dobara chalayein. Jab tak sab [OK ] na ho, dohraate rahein.

✅ Aakhir mein: Setup complete. Start Sentinel: .\start.ps1

4. Naya PC (3/4): .env File Bharna

.env project folder mein ek text file hai jis mein is PC ki settings aur passwords hain. setup.ps1 ne ise .env.example se bana diya hai. Ise Notepad mein kholein:

notepad .env

Ye lines zaroor bharein (= ke baad, bina space):

LineKis kaam kiKya likhna hai
Jwt__SigningKey=Login ka "mohar" (session sign karta hai)Lambi random chaabi, kam az kam 32 huroof (neeche command)
Device__ApiKey=AI service ka password (AI → Server)Doosri random chaabi
Device__SensorApiKey=Sensors aur simulator ka passwordTeesri random chaabi. ⚠️ Device__ApiKey se alag honi chahiye, warna setup/Server mana kar deta hai
Seed__AdminEmail=Pehle Admin ka login emailJaise admin@sentinel.local
Seed__AdminPassword=Pehle Admin ka password (sirf khali, naye database par kaam aata hai)Apna mazboot password
ConnectionStrings__Sentinel=Database ka pataDeveloper (default naam): waise hi chhor dein (Server=localhost;…). Express: Server=localhost ko Server=localhost\SQLEXPRESS karein

Random chaabi banane ki command (PowerShell):

[Convert]::ToBase64String((1..48 | % {Get-Random -Max 256}))

Jo text aaye, copy karke = ke baad paste karein. Har chaabi ke liye command alag se dobara chalayein. Save karein (Ctrl + S).

Baqi lines ikhtiyari hain (khali chhor sakte hain): SMS (Twilio), WhatsApp, Email, Firebase, Web Push. Inhein sirf tab bharein jab wo channel chahiye (Chapter 19). Telegram aur GSM modem Optional / Legacy — Not Part of Current Scope hain: setup mein inhein khali hi rehne dein.

⚠️ .env mein passwords hain. Ise kisi ko na bhejein, email/WhatsApp na karein, git mein na daalein, internet par na daalein. Har PC ki apni .env hoti hai. Firebase ki service-account JSON file bhi project folder ke bahar rakhein.

5. Naya PC (4/4): Database, Start, Login, Stop

Qadam 1: Database (do mein se ek raasta)

Raasta A: shared copy restore karna (doosre PC wala data, users aur naqshe saath; SQL Server 2022 ya naya chahiye):

.\database\load.ps1

Ye poochta hai: yes likh kar Enter. ✅ "Restored SentinelDb…". ⚠️ Is PC par pehle se SentinelDb ho to wo poora badal jata hai. Express par: .\database\load.ps1 -Server "localhost\SQLEXPRESS". Login wohi email/password jo us data mein tha.

Raasta B: bilkul naya, khali database: pehle SQL Server mein SentinelDb naam ka khali database banayein (SQL Server Management Studio → Databases → Right click → New Database). Phir:

sentinel-django\.venv\Scripts\python sentinel-django\manage.py create_schema

✅ "Created the Sentinel tables in 'SentinelDb' …". Ye sirf khali database par chalta hai; tables pehle se hon to mana kar deta hai (data mehfooz). Pehla Admin .env wale Seed__AdminEmail / Seed__AdminPassword se banta hai.

⚠️ SentinelDb par manage.py migrate kabhi na chalayein. (System khud bhi ise rokta hai.)

Ab .\setup.ps1 dobara chalayein: ✅ sab [OK ] aur "Setup complete".

Qadam 2: System chalana

.\start.ps1

Ek supervisor window khulti hai (ise band na karein; ye Server aur AI service chalati hai aur gir jayein to dobara chalati hai). PowerShell intezar karti hai jab tak Server aur AI models tayyar na hon. ✅ Aakhir mein: Sentinel is running. Dashboard: http://localhost:5291 Stop: .\stop.ps1

Aag ka demo bhi chahiye (nakli cameras/sensors, aur Warehouse mein nakli aag):

.\start.ps1 -Simulator

Qadam 3: Browser mein kholna aur login

  1. Chrome ya Edge mein http://localhost:5291 kholein.
  2. .env wala Seed__AdminEmail aur Seed__AdminPassword likh kar Sign in (Chapter 8).
  3. ✅ Overview page khule, upar header mein Live.

Qadam 4: Band karna

.\stop.ps1

✅ "Sentinel stopped. Ports … are free." Data database mein mehfooz rehta hai. (Script block ho to: powershell -ExecutionPolicy Bypass -File .\start.ps1 / .\stop.ps1.)

6. Safe Test Mode (Test Se Pehle Zaroor)

Masla: agar .env mein asli Twilio (SMS/WhatsApp), Telegram, Email, Firebase ya GSM ki settings hain, to test mein aag ya emergency bani to system asli logon ko asli message bhej dega.

Hal: test ke dauran alert channels band karna

  1. .env Notepad mein kholein.
  2. In lines ke shuru mein # laga dein (# wali line system parhta hi nahi):
#Notifications__Sms__TwilioAccountSid=...
#Notifications__Sms__TwilioAuthToken=...
#Notifications__WhatsApp__TwilioAccountSid=...
#Notifications__WhatsApp__TwilioAuthToken=...
#Notifications__Telegram__BotToken=...
#Notifications__Email__SmtpHost=...
#Notifications__Fcm__ProjectId=...
#Notifications__Gsm__Port=...
  1. Save karein, phir .\stop.ps1 aur .\start.ps1.

Is ke baad kya hoga:

  • Notifications page ke "Alert channels" mein ye channels Not configured dikhenge. Koi SMS/WhatsApp/Telegram nahi jayega.
  • Email: asal mein nahi jata, us ka text Server ke log (logs\django.log) mein likha jata hai ("console mode").
  • Browser alerts: sirf usi browser par jahan aap ne khud Enable Alerts dabaya ho.

Test khatam hone ke baad # hata dein, aur stop/start karein, taake asli alerts dobara chalein.

7. Roz Ka Kaam: Chalana Aur Band Karna

Project folder mein PowerShell kholein:

.\start.ps1               # chalana (demo ke liye: .\start.ps1 -Simulator)
# browser: http://localhost:5291
.\stop.ps1                # band karna

Supervisor window khuli rehne dein. Agar .\start.ps1 kahe "Sentinel is already running", to system pehle se chal raha hai: bas browser kholein.

Database doosre PC se (office ↔ ghar)

Dono PCs par ek jaisa data rakhne ke liye database ek backup file (database\SentinelDb.bak) ban kar git se jata hai.

Kaam khatam karte waqt (jis PC par kaam kiya):

.\stop.ps1
.\database\save.ps1
git add database\SentinelDb.bak
git commit -m "db: update"
git push

Doosre PC par kaam shuru karte waqt:

.\stop.ps1
git pull
.\database\load.ps1
.\start.ps1

"yes" likhein. ✅ "Restored SentinelDb…". Database poora badal jata hai.

⚠️ Ek waqt mein ek hi PC par kaam karein. Dono jagah data badla aur save/load bhool gaye, to ek jagah ka kaam mit jayega. .env git mein nahi jati: har PC ki apni.

8. Login Karna

  1. Browser (Chrome/Edge) kholein: http://localhost:5291
  2. Email: .env wala Seed__AdminEmail (jaise admin@sentinel.local), ya restore kiye data ka email.
  3. Password: Seed__AdminPassword (naye database par), ya restore kiye data ka password.
  4. Sign in dabayein.

✅ Overview page khul jaye aur upar header mein Live likha ho.

Ghalat password: laal message aayega. Login 8 ghante tak chalta hai, phir dobara login. Logout header mein daen taraf hai.

C · Har feature ka test

10. Test 1: Aag Ka Demo (Simulator)

Maqsad: dekhna ke aag lagne par poora system kaise react karta hai.

⚠️ Pehle Safe Test Mode (Chapter 6) karein. Is demo mein insaan danger zone mein aate hain, jo emergency hai, aur alerts chalte hain.

Qadam:

  1. System band ho to: .\start.ps1 -Simulator. (Chal raha ho to pehle .\stop.ps1.) Ye nakli cameras/sensors chalata hai aur Ground Floor - Warehouse mein nakli aag lagata hai.
  2. Login karein aur Overview dekhein.

✅ Kya dikhna chahiye (1–2 minute mein):

  • Live Cameras par dabbe hilte hue, SIMULATED DATA nishan.
  • Warehouse Floor camera par bhara laal aag ka dabba.
  • Header chip laal CRITICAL ALERT, Overview banner Emergency. Alarm lagatar bajta hai (Resolve ya 🔊 tak).
  • Incidents mein naya incident, "Ground Floor - Warehouse", High/Critical; sidebar par laal badge.
  • Activity Log mein lines: incident khula, notifications.
  • Sensors par Warehouse ki garmi/dhuwan barhti hui.
  • Sprinklers: Warehouse ke Auto sprinklers khud Active (demo setting mein simulated data par bhi; is project mein sirf database, koi asli hardware nahi).

Band karna: .\stop.ps1, phir simulator ke baghair .\start.ps1.

Camera lost check (simulator ke baghair chalane ke baad):

  • ~10–12 second baad Incidents mein har nakli camera ke liye "Camera lost: no frames from … for 10 s".
  • Warehouse ke cameras (jahan aag thi) High, baqi Medium. Test ke baad sab Resolve kar dein.

11. Test 2: AI Settings (Photo Aur Sensitivity)

A. AI ko photo dikhana

Test photo: aag/dhuwan wali koi bhi photo (JPG/PNG, 5 MB tak), aur ek bina aag wali photo (insaan wali).

  1. .\start.ps1 chal raha ho. Sidebar → AI Settings.
  2. ✅ AI service ka haal hara, dono models (person, fire_smoke) loaded; sidebar mein AI Settings ke aage hara nukta.
  3. Test with a picture → photo chunein → Analyze. 1–3 second intezar.
  • Photo par dabbe: aag laal, dhuwan narangi, insaan hara; table mein Class, Confidence, Box, Why.
  • Bina aag wali photo par aag ka dabba na aaye.

Ye sirf preview hai: koi incident, alert ya sprinkler nahi chalta. Ek photo mein 3-frame check nahi hota, is liye live camera se zyada false alarm ho sakte hain.

B. Sensitivity slider (sirf Admin)

Tasveer: AI Settings, simulated test data.

  1. fire_smoke model ke card par Detection threshold slider (0.25 = More sensitive … 0.55 = Fewer alerts). Default: fire_smoke 0.40, person 0.45.
  2. Slider ko misaal 0.35 par le jayein: value saath saath dikhe, "(current 0.40)" bhi.
  3. Apply dabayein.
  • Naya value tab hi "active" dikhe jab AI service ne use maan liya ho.
  • Activity Log mein SettingChanged line.
  • .\stop.ps1 + .\start.ps1 ke baad bhi wohi value (ye ai-service\models\thresholds.local.json mein mehfooz hoti hai). Test ke baad wapas 0.40 karein.

⚠️ Kam value = zyada sensitive: zyada alerts aur zyada false alarms. Zyada value = kam alerts, lekin asli aag chhoot sakti hai.

Masla: laal OFFLINE = AI service band (.\stop.ps1, .\start.ps1, logs\ai.log dekhein). "some models missing" / "sha256 mismatch" = model file nahi ya kharab (.\setup.ps1 bata dega).

12. Test 3: Sensor Ko Garam Karna (PowerShell)
